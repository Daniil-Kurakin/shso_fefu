# Сайт Штаба студенческих отрядов ДВФУ (ШСО ДВФУ)

Корпоративный веб-сервис для управления студенческими отрядами Дальневосточного федерального
университета. Объединяет каталог отрядов, новостную ленту, систему заявок, базу знаний и
Telegram-уведомления в единый цифровой рабочий инструмент штаба.

```
│   ├── news/               # Новости и фотогалереи
│   ├── vacancies/          # Вакансии / объявления о наборе
│   ├── requests/           # Заявки на бронирование помещений, пропуска, запросы штаба
│   ├── events/             # Календарь событий (ручные события + запросы штаба)
│   ├── bot/                # Telegram-бот: вебхук, отправка уведомлений
│   └── content/            # Конструктор страниц, база знаний, FAQ, глоссарий, цитаты
├── config/
│   ├── settings/
│   │   ├── base.py         # Общие настройки
│   │   ├── dev.py          # Разработка
│   │   ├── prod.py         # Продакшен
│   │   └── test.py         # Тесты
│   ├── urls.py             # Корневой роутинг
│   ├── wsgi.py
│   └── asgi.py
├── templates/
│   ├── base.html           # Базовый шаблон
│   └── includes/           # Шапка, подвал, сообщения
├── static/                 # CSS, JS, шрифты, изображения
├── locale/                 # Переводы (ru / en)
├── tests/                  # Интеграционные тесты
├── docker-compose.yml
├── Dockerfile
└── pyproject.toml
```

### Принципы архитектуры

- **Одно Django-приложение — один домен.** Каждый бизнес-объект живёт в своём `apps/`.
- **Нет дублирования данных.** Запросы штаба (`HQRequest`) отображаются в календаре через
  динамический запрос — без создания дополнительных копий или сигналов синхронизации.
- **Настройки из окружения.** Все чувствительные значения берутся из `.env` через обёртки
  `env()`, `env_bool()`, `env_int()`, `env_list()`.
- **Роль автоматически синхронизируется** при изменении членства (`Membership.save()`).
- **Кэш до полуночи.** Цитата дня и настройки сайта кэшируются в Redis с TTL до конца суток
  (Asia/Vladivostok).

## 3. Структура приложений

### `apps.accounts` — Учётные записи
Аутентификация по e-mail (case-insensitive), расширенный профиль, портфолио бойца.

**Ключевые компоненты:**
- `EmailCIBackend` — кастомный backend: логин по email без учёта регистра
- `UserManager` — создание пользователей и суперпользователей
- Поля профиля: ФИО, телефон, аватар, bio, ВКонтакте, Telegram
- Аудит 152-ФЗ: `consent_personal_data`, `consent_date`, `consent_ip`

### `apps.squads` — Отряды
Полный жизненный цикл отряда: создание, состав, переводы, страница отряда.

**Ключевые компоненты:**
- `Direction` — направление деятельности (педагогическое, строительное и т.д.)
- `Position` — справочник должностей (`is_staff` → автоматически присваивает роль SQUAD_STAFF)
- `Squad` — отряд (логотип, девиз, набор, контакт)
- `Membership` — членство с историей, статусом ветерана, constraint «один активный»
- `SquadPageRevision` — черновики и согласование страниц отрядов (Draft → Pending → Published)
- `SquadTransferRequest` — атомарный перевод бойца между отрядами

### `apps.news` — Новости
Создание, согласование и публикация новостей с фотогалереей.

**Ключевые компоненты:**
- `News` — статья (slug, категория, организатор, обложка, статус)
- `NewsImage` — фотографии галереи
- Workflow: Draft → Pending → Published / Returned
- Уведомление автора в Telegram при публикации и возврате

### `apps.vacancies` — Вакансии
Объявления о вакансиях отрядов и штаба.

### `apps.requests` — Заявки
Три независимых типа заявок, доступных только комсоставу отряда и выше.

**Компоненты:**
- `CampusPremise` — справочник помещений кампуса ДВФУ (корпуса A–M)
- `RoomBookingRequest` + `BookedPremise` — заявка на бронирование аудиторий
  (несколько аудиторий в одной заявке, раздельное согласование каждой, проверка коллизий)
- `PassRequest` + `PassVisitor` — заявка на пропуск гостей на территорию кампуса
  (автоочистка ПДн через 30 дней после визита — 152-ФЗ)
- `HQRequest` + `HQRequestResponse` — запросы штаба: мероприятия для волонтёрской деятельности
  бойцов (уровни: вузовский → международный, интеграция с добро.рф)

### `apps.events` — Календарь событий
Месячный интерактивный календарь с объединённым отображением событий и запросов штаба.

**Компоненты:**
- `Event` — ручное событие штаба (категория, дата, время, локация, обложка, iCal-экспорт)
- `CalendarView` — динамически объединяет `Event` и `HQRequest` без дублирования в БД
- Режимы: сетка месяца и список (agenda); фильтры и поиск
- Экспорт `.ics` (RFC 5545) для подписки в Google/Apple Calendar

### `apps.bot` — Telegram-бот
Webhook-сервер + слой отправки уведомлений.

**Компоненты:**
- `notify_user_async()` — постановка уведомления в фоновую очередь Django-Q2
- Уведомления срабатывают при: публикации/возврате новости, одобрении/отклонении ревизии
  страницы отряда, результатах бронирования (с раздельным списком аудиторий), пропусков

### `apps.content` — Контент и конструктор страниц
Статический и динамический контент сайта.

**Компоненты:**
- `Quote` — «Цитата дня» с закреплением на конкретную дату, детерминированный выбор
- `StaffMember` — руководящий состав штаба (страница «Контакты»)
- `SiteSetting` — ключевые показатели и настройки сайта (кэш 1 час)
- `KnowledgeCategory` + `KnowledgeArticle` — база знаний с вложениями
- `FAQCategory` + `FAQItem` — часто задаваемые вопросы
- `GlossaryTerm` — отрядный глоссарий (алфавитная группировка)
- `CustomPage` + `PageBlock` — конструктор страниц: блоки типа hero, text, cards, accordion, cta,
  quote, gallery с настройкой шрифта, размера, выравнивания, цвета и размера изображений

## 4. Модели данных

### ER-диаграмма (упрощённая)

```
User ──┬── Membership ── Squad ── Direction
       │          └── Position
       ├── UserPortfolioItem
       ├── News ── NewsImage
       ├── RoomBookingRequest ── BookedPremise ── CampusPremise
       ├── PassRequest ── PassVisitor
       ├── HQRequest ── HQRequestResponse
       ├── Event
       ├── SquadPageRevision
       └── SquadTransferRequest
```

### Ключевые связи
- `User` ↔ `Squad` через `Membership` (история членства, one-active constraint)
- `HQRequest` виден в `Calendar` без FK — динамический join в слое представления
- `Membership.save()` автоматически обновляет `User.role`
- `SquadPageRevision.publish()` атомарно обновляет публичные поля `Squad`

## 5. Ролевая модель

| Роль | Код | Описание |
|---|---|---|
| Владелец | `owner` | Полный доступ, Django-администратор, редактирование конструктора страниц |
| Администратор | `admin` | Модерация заявок, новостей, ревизий, создание запросов штаба |
| Куратор | `curator` | Сотрудник штаба с расширенными правами просмотра |
| Комсостав отряда | `squad_staff` | Подача заявок, бронирование, редактирование страницы своего отряда |
| Боец / участник | `member` | Просмотр, отклик на запросы штаба |
| Ветеран | — | Завершил активную деятельность (`Membership.is_veteran=True`) |
| Кандидат | — | Зарегистрированный пользователь без активного членства |

**Свойства `User` для проверок в коде:**

| Свойство | Доступ |
|---|---|
| `is_hq_staff` | `owner`, `admin`, `curator` или `is_superuser` |
| `is_squad_command_staff` | `is_hq_staff` или активная должность с `position.is_staff=True` |
| `is_owner` | `owner` или `is_superuser` |
| `can_manage_hq_requests` | `owner`, `admin`, `is_superuser` |
| `is_fighter_or_staff` | любой с активным членством в отряде |
| `is_veteran` | `Membership.is_veteran=True` |

## 6. Логика бизнес-процессов

### Согласование страницы отряда
```
Комсостав сохраняет черновик (Draft)
  → Отправляет на согласование (Pending)
  → Штаб одобряет (Published): данные применяются к Squad.save() + TG-уведомление
  → или возвращает с комментарием (Returned) + TG-уведомление
```

### Бронирование помещений
```
Комсостав подаёт заявку (одна + несколько аудиторий)
  → Штаб рассматривает каждую аудиторию (BookedPremise) отдельно
  → Одобренные и отклоненные аудитории перечисляются в TG-уведомлении раздельно
  → sync_status() обновляет общий статус заявки на основе статусов аудиторий
  → Коллизии по времени блокируются на уровне clean()
```

### Запрос пропуска (152-ФЗ)
```
Комсостав подаёт заявку с данными гостей (PassVisitor)
  → Штаб одобряет / отклоняет + TG-уведомление
  → data_deletion_scheduled_at = visit_date + 30 дней
  → Фоновая задача Django-Q2 вызывает purge_personal_data() после истечения срока
```

### Перевод бойца между отрядами
```
Командир исходного отряда создаёт SquadTransferRequest + документ
  → Штаб рассматривает
  → approve() [atomic]: закрывает старое Membership + создаёт новое
  → Роль User обновляется автоматически через Membership.save()
```

### Запросы штаба (HQRequest)
```
Администратор создаёт запрос (событие, волонтёрская задача)
  → Бойцы и комсостав видят запрос и могут откликнуться (HQRequestResponse)
  → Запрос автоматически отображается в Календаре событий
  → Ссылка на добро.рф показывается только если поле заполнено
```

### Перевод в ветераны
```
Комсостав своего отряда вызывает Membership.convert_to_veteran()
  → is_active=False, is_veteran=True, end_date=today
  → Если был SQUAD_STAFF и нет других активных должностей → роль понижается до MEMBER
```

### Новости
```
Любой авторизованный пользователь создаёт черновик (Draft)
  → Отправляет на согласование (Pending): появляется в очереди модераторов
  → Штаб публикует (Published) + TG-уведомление автору
  → или возвращает с комментарием (Returned) + TG-уведомление
```

### Цитата дня
```
get_quote_of_the_day():
  1. Проверяем закреплённую цитату на сегодня (pinned_date)
  2. Если нет — детерминированно выбираем по today.toordinal() % count
  3. Кэшируем в Redis до полуночи Asia/Vladivostok
```

## 8. Безопасность и соответствие законодательству

| Мера | Реализация |
|---|---|
| Пароли | Argon2 (основной), PBKDF2 (резервный) |
| Email | Нормализация в lowercase + UniqueConstraint на Lower(email) |
| CSRF | Стандартный Django middleware |
| Clickjacking | XFrameOptionsMiddleware |
| 152-ФЗ «О персональных данных» | Поля `consent_personal_data`, `consent_date`, `consent_ip`; автоочистка ПДн гостей через 30 дней (`purge_personal_data()`) |
| Django-admin | Доступен только роли `owner` / `is_superuser` (принудительно в `User.save()`) |
| Права на заявки | Бронирование и пропуска доступны только комсоставу и выше |
| Права на конструктор | Редактирование `CustomPage` только у `owner` |
